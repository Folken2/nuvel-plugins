# Build an agent with nuvel

nuvel stamps out a production skeleton (FastAPI server with auth and health
checks, a 17-plugin chain for cost, tracing, caching, resilience and
guardrails, Dockerfile, Railway config, tests) so you spend your time on what
the agent actually does. The skeleton is free; the tools, prompt and skills
are the work.

Every other skill in this plugin is framework knowledge. This one is the
workflow: run it top to bottom, and open a knowledge skill when a step needs
it. Treat each numbered step as a checkpoint: check it worked before the
next one.

## 1. Pick the framework

| The user wants… | Framework | Scaffold flag |
|---|---|---|
| A general agent, API service, multi-step workflow, voice agent (default) | Google ADK | *(none)* |
| A personal bot with a persistent persona, mostly on Telegram | Hermes | `--framework hermes` |
| An agent on the Claude Agent SDK | Claude Agent SDK | none — write it by hand (see below) |

When unsure, pick ADK. For Claude Agent SDK projects, nuvel's scaffold target
is deprecated: skip step 3, create the project yourself, and follow the
`claude-sdk-*` skills (start with `../claude-sdk-tool-creation/SKILL.md` and
`../claude-sdk-deployment/SKILL.md`). For Hermes, read `../hermes/SKILL.md`
before scaffolding.

## 2. Confirm the spec

Get three things, silently if they are clear from context, by asking if not:

- **Name:** kebab-case, starts with a letter, at most 40 characters
  (`support-triage`). The Python package inside becomes snake_case
  (`support_triage`); always pass the kebab name to the CLI.
- **One-line description.**
- **What it does:** the 2–4 tools it needs and what users will say to it. For
  a vague brief ("an agent that helps with sales"), propose concrete tools and
  ask whether that is the shape before scaffolding.

## 3. Scaffold

Check the CLI first: `nuvel --help`. If it is missing, run it without
installing through `uvx --from nuvel-cli nuvel …` (needs `uv`), or ask the
user before installing it with `pipx install nuvel-cli`. The PyPI package is
`nuvel-cli`; the bare `nuvel` package on PyPI is something else. Below,
`nuvel` means whichever form works.

```bash
nuvel agent create <kebab-name> --description "<one line>" --output-dir . [flags]
```

ADK flags (choose now; they are hard to add later):

| Flag | Use when |
|---|---|
| `--workflow` | The work branches: plan→execute, triage→route, draft→review. Root agent becomes an ADK 2.0 `Workflow` graph. Read `../adk-workflow-graphs/SKILL.md` and `../adk-task-delegation/SKILL.md` before editing it. |
| `--with-composio` | The agent's value is breadth of integrations (Gmail, GitHub, Slack, Notion…). Needs `COMPOSIO_API_KEY`. See `../adk-composio-tool-router/SKILL.md`. |
| `--with-slack` / `--with-telegram` / `--with-teams` | Users talk to it in that app. Slack implies Composio. |
| `--persona` | A long-lived personal agent that should develop a character (self-rewriting `SOUL.md`, writes its own skills). Never for support bots or anything that must behave the same after every deploy. |
| `--with-acp` | It should run from a terminal or plug into ACP clients (editors). |
| `--with-eval` | Start with an eval suite (`nuvel evalv2 run`). Recommended for anything going to production. |

Check (ADK): the new folder has `<snake_name>/`, `run_adk.py`, `requirements.txt`,
`.env.example` and `tests/`.

## 4. Fill in the brain

Work inside `<kebab-name>/<snake_name>/`. Open the knowledge skill for each
part before writing it; ADK has non-obvious conventions and the skills hold the
exact signatures.

1. **Shape.** If it is more than one agent or step, decide the topology first:
   `../adk-agent-patterns/SKILL.md`.
2. **Tools** in `tools/`, one file per tool, registered in `agent.py`:
   `../adk-tool-creation/SKILL.md`. Return structured dicts, use
   `ToolContext` for state, and give each tool a docstring the model can act on.
3. **System prompt** in `prompt/instructions.py`:
   `../adk-prompt-engineering/SKILL.md`. Use an `InstructionProvider` for
   anything that depends on state.
4. **Domain skills** in `skills/<slug>/SKILL.md` for knowledge the agent needs
   at runtime (policies, API quirks, lookup tables). They are picked up
   automatically. Choose a shape with `../adk-skill-design-patterns/SKILL.md`,
   then write it with `../adk-skill-creation/SKILL.md`.
5. **Approvals and hooks** if it takes actions with side effects:
   `../adk-callbacks-hitl/SKILL.md`.
6. **Tests** in `tests/`: a unit test per tool, following the existing tests.

Then read whichever of these applies:

| If the agent… | Read |
|---|---|
| runs unattended or for a long time | `../adk-long-horizon-guardrails/SKILL.md`, `../adk-long-horizon-sessions/SKILL.md` |
| runs on a schedule | `../adk-cron-isolation/SKILL.md` |
| speaks or sees in real time | `../adk-streaming/SKILL.md` |
| shares memory across a team or organisation | `../adk-org-memory-retrieval/SKILL.md` |
| should improve itself over time (experimental) | `../adk-memory-self-improvement/SKILL.md` |

## 5. Verify

```bash
cd <kebab-name>
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest pytest-asyncio
python -m pytest tests -q
python -c "from <snake_name>.agent import root_agent; print(root_agent.name)"
nuvel doctor --path .
```

Tests and the import must pass before you say the agent is done; the
scaffold ships a single smoke test, so the tests that count are the ones you
wrote in step 4. `nuvel doctor` reports a missing `.env` and
`OPENROUTER_API_KEY` as failures until the user adds a key; anything else it
fails needs fixing. To run it, the user
copies `.env.example` to `.env` and adds an `OPENROUTER_API_KEY` (any
LiteLLM model works; see `<snake_name>/config/llm.py`); then
`DEV_MODE=true python run_adk.py` serves it on `http://localhost:8000`, or
`DEV_MODE=true adk web .` opens the ADK web UI. Never write a real key into a
file yourself.

## 6. Hand over

Tell the user, in a few lines: what the agent does, the tools you wrote, how
to run it, and what it still needs (keys, Postgres for production sessions via
`SESSION_SERVICE_URI`, a deploy target). The project already includes a `Dockerfile`
and `railway.json`.

## Pitfalls

- `nuvel run` starts nuvel's own meta-agent server; it does not create files.
  Use `nuvel agent create`.
- `--system-prompt` pastes text into the template as is. Write the prompt in
  `prompt/instructions.py` instead.
- Don't add custom `list_skills` / `read_skill` tools: the scaffold already
  wires ADK's `SkillToolset`, which does that.
- The generated project does not import `nuvel` at runtime; it is yours to
  move, rename and deploy anywhere.
- nuvel prints a couple of dependency warnings on stderr. They are harmless;
  add `2>/dev/null` if they get in the way.
